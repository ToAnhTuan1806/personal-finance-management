### Concurrent upsert

`BudgetSql` dùng `CyclicBarrier(2)` dừng hai INSERT ngay sau các precheck thật, trước khi thực thi SQL. Không thay SQL, tham số hay kết quả query; không dùng Thread.sleep. Hai request chạy trên thread/transaction riêng; timeout hữu hạn và executor được dọn trong finally.

Kỳ vọng và kết quả lượt riêng: **một 200 + một 409, DB có đúng một bản ghi**. Ca này kiểm chứng luồng HTTP dịch duplicate MySQL thực tế. Ca FK riêng dùng exception JDBC thật để xác nhận 1452 không bị chuyển thành 409; các test MVC đã có trong Commit 2 kiểm tra định dạng ApiError cho duplicate và lỗi DB khác.

## Migration và Hibernate validate

Suite [CategoryBudgetMigrationIntegrationTests](../../backend/src/test/java/com/smartexpense/backend/CategoryBudgetMigrationIntegrationTests.java) là gate riêng, **không dùng schema JPA làm bằng chứng migration**:

1. Yêu cầu đúng một SQL artifact cho mỗi version V001 baseline, V002 metadata và V003 category_budgets theo kế hoạch hiện hành. Không suy đoán tên hậu tố; tìm theo version trong `database/migrations/`. Nếu DB chốt chuỗi khác, phối hợp điều chỉnh test trong phạm vi riêng được duyệt.
2. Thiếu artifact thì FAIL với thông báo `BLOCKED D07-DB` trước khi tạo container/kết nối; không skip và không tự viết DDL thay thế.
3. Khi đủ migration đã duyệt: dùng MySQL mới trống, áp V001/V002, thêm MonthlyBudget tổng hợp, áp V003, rồi khởi động Spring với JPA action=none và ddl-auto=validate. Gọi thêm Hibernate SchemaManager.validateMappedObjects() tường minh.
4. Đối chiếu bảng/cột/NOT NULL/BIGINT/INT/DECIMAL(15,2), ID auto_increment, UNIQUE đúng bốn cột, FK users/categories và DELETE RESTRICT/NO ACTION; so sánh nguyên dòng MonthlyBudget trước/sau V003.

**Hiện BLOCKED:** nhánh chỉ có `V002__category_icon_color.sql`; chưa có V001 và V003. Chưa xác nhận đường chạy thành công của suite migration, Hibernate validate trên schema migration, bảo toàn dữ liệu qua V003 hoặc chính sách FK của artifact D07 thật. Kết quả UNIQUE/FK trên schema harness ở trên chỉ chứng minh mapping JPA và hành vi MySQL của schema đó.

## Chạy lại và phối hợp

Trong `backend/`, JDK 21 và Docker Linux engine local sẵn sàng:

```powershell
.\gradlew.bat --offline compileJava compileTestJava test verifyD03IntegrationTests --continue --console=plain
```

Chạy riêng API D07 hoặc gate migration:

```powershell
.\gradlew.bat --offline test --tests '*CategoryBudgetIntegrationTests' --console=plain
.\gradlew.bat --offline test --tests '*CategoryBudgetMigrationIntegrationTests' --console=plain
```

Docker trong sandbox ban đầu báo access denied; kiểm tra ngoài sandbox xác nhận engine Linux hoạt động và cho phép chạy Testcontainers. Không cần thay cấu hình Docker, CI/CD, dependency hoặc production. Không đọc `.env`, dùng credential/khóa test ngẫu nhiên.

Quỳnh cần cung cấp/review chuỗi migration tạo schema sạch và chính sách xóa/đổi loại category có budget. Khi có artifact đúng baseline, chạy gate migration và toàn bộ regression lại, đối chiếu XML, rồi cập nhật kết luận tại đây. Chưa nghiệm thu D07-BE đầy đủ khi migration hoặc regression còn bị chặn.

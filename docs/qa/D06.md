**Rủi ro còn lại:** chống trùng ở Service không bảo đảm uniqueness khi request ghi đồng thời. Test chặn hai INSERT cho tới khi cả hai SELECT kiểm tra đã xong; không mock kết quả hoặc thay SQL. UPDATE cũng có cửa sổ tương tự. Muốn bảo đảm tuyệt đối cần nhóm duyệt phương án riêng, gồm chuẩn hóa/collation, dữ liệu trùng cũ và ràng buộc hoặc cơ chế serialize phù hợp.

V002 chỉ được kiểm thử trên MySQL **8.0.46** cô lập. Fixture: **2 user / 4 category / 3 transaction / 1 budget**; dump **6.324 byte**, restore/validate PASS, hash dữ liệu và khóa không đổi. SHA-256 V002: `02dfb91fbf51b88eacb2e4e90b79beec1e3dda822f7d03e8f0fa0b54498ae8ff`. SHA-256 dump tổng hợp R06: `ebb9418cbb249609dd2e1f9ea58379466256db9cbfe03197c25be648441deb22`. Checksum dump chỉ áp dụng artifact đúng lượt; không dùng dump test để xác nhận production.

Master Plan còn ghi backfill D06 trong khi API hiện hành giữ NULL/fallback. Đây là điểm cần nhóm chốt riêng; không tự backfill hoặc chạy migration VPS trong QA.

## SQL và migration compatibility

Đối chiếu độc lập, chỉ trong MySQL test:

```sql
SELECT id FROM transactions
WHERE user_id=? AND transaction_date=? ORDER BY transaction_date DESC,id DESC;
SELECT COALESCE(SUM(amount),0) FROM transactions
WHERE user_id=? AND transaction_date=? AND type=?;
SELECT column_name,column_type,is_nullable FROM information_schema.columns
WHERE table_schema=DATABASE() AND table_name='categories' AND column_name IN ('icon','color');
```

- Sáu ca biên ngày: mỗi ca A có đúng1 giao dịch Thu1.23, Chi0 vào ngày chọn; giao dịch B999.99 và ngày kề bị loại. Ngày29/02 có27 Chi0.01 →0.27. So sánh API Calendar với SQL BigDecimal, không suy tổng từ trang10 dòng.
- Schema HTTP test: `icon varchar(40) YES`, `color varchar(7) YES`, đủ4 FK và unique budget(user/year/month), không transaction mồ côi hoặc category sai owner.
- Migration fixture/backup/restore dùng lại `D06MigrationIntegrationTests`: source và restore là hai container riêng, dữ liệu tổng hợp **2 users / 4 categories / 3 transactions / 1 budget**. Hash dữ liệu và FK/unique không đổi;4 category cũ vẫn NULL, ứng dụng đọc fallback; Hibernate validate PASS. Backup/restore và phục hồi schema drift PASS; checksum sai bị chặn trước restore.
- Bằng chứng dump tổng hợp lượt này: **6,324 bytes**, SHA-256 `a353581af7d0f5c94faf94dbf6d3a5859de07286564a00b3d0b080fd8cd6b069`; V002 SHA-256 `02dfb91fbf51b88eacb2e4e90b79beec1e3dda822f7d03e8f0fa0b54498ae8ff`. Dump nằm trong build bị Git ignore, không phải backup production.
- V002 được triển khai production theo thông tin người dùng; kiểm thử local không xác minh trạng thái database VPS. Không đọc backup thật, không chạy migration hoặc truy cập VPS trong lượt này.

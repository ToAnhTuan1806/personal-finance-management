## 2. Chi tiết Schema Migration V004

File migration: `database/migrations/V004__create_recurring_templates.sql`

```sql
-- D08-DB: apply to the verified schema after V003; never use this file as a baseline.
-- If recurring_templates already exists, stop and compare its schema/history; do not rerun with --force.
-- Owner/category type and input validation remain in the Backend; foreign keys only enforce existence.
SET SESSION lock_wait_timeout = 10;

CREATE TABLE recurring_templates (
    id BIGINT NOT NULL AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    category_id BIGINT NOT NULL,
    type VARCHAR(20) NOT NULL,
    amount DECIMAL(15,2) NOT NULL,
    day_of_month INT NOT NULL,
    note VARCHAR(500) NULL DEFAULT NULL,
    active TINYINT(1) NOT NULL DEFAULT 1,
    PRIMARY KEY (id),
    CONSTRAINT fk_recurring_templates_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE RESTRICT ON UPDATE RESTRICT,
    CONSTRAINT fk_recurring_templates_category
        FOREIGN KEY (category_id) REFERENCES categories(id)
        ON DELETE RESTRICT ON UPDATE RESTRICT,
    CONSTRAINT chk_recurring_templates_type
        CHECK (type IN ('INCOME', 'EXPENSE')),
    CONSTRAINT chk_recurring_templates_amount
        CHECK (amount > 0),
    CONSTRAINT chk_recurring_templates_day_of_month
        CHECK (day_of_month BETWEEN 1 AND 31),
    CONSTRAINT chk_recurring_templates_active
        CHECK (active IN (0, 1)),
    INDEX idx_recurring_templates_user_active
        (user_id, active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### Phân tích kiến trúc kỹ thuật:
1. **Kiểu dữ liệu và tương thích JPA:**
   - `id`: `BIGINT NOT NULL AUTO_INCREMENT` khớp `@Id @GeneratedValue(strategy = GenerationType.IDENTITY) Long id`.
   - `user_id`, `category_id`: `BIGINT NOT NULL` tương ứng `@ManyToOne(fetch = FetchType.LAZY, optional = false)` liên kết `User` và `Category`.
   - `type`: `VARCHAR(20) NOT NULL` kết hợp `CHECK (type IN ('INCOME', 'EXPENSE'))` tương thích `@Enumerated(EnumType.STRING)` của `TransactionType`.
   - `amount`: `DECIMAL(15,2) NOT NULL` bảo toàn độ chính xác tài chính 15 chữ số, 2 số thập phân.
   - `day_of_month`: `INT NOT NULL` lưu ngày trong tháng (1 đến 31).
   - `note`: `VARCHAR(500) NULL` cho phép `null` hoặc chuỗi Unicode đến 500 ký tự.
   - `active`: `TINYINT(1) NOT NULL DEFAULT 1` kết hợp `CHECK (active IN (0, 1))` tương thích kiểu boolean chuẩn của MySQL và ánh xạ `boolean active` / `BIT(1)` của Hibernate qua tham số `tinyInt1isBit=true`.
2. **Ràng buộc an toàn:**
   - 2 Khóa ngoại `ON DELETE RESTRICT ON UPDATE RESTRICT` ngăn ngừa tuyệt đối hành vi cascade xóa ngoài ý muốn.
   - Không áp dụng UNIQUE trên `(user_id, category_id, day_of_month)` nhằm cho phép người dùng có nhiều mẫu định kỳ trong cùng một danh mục và cùng một ngày.
   - Timeout phiên `SET SESSION lock_wait_timeout = 10;` tránh hiện tượng giữ metadata lock kéo dài.

## 6. Release Gate & Hướng dẫn Vận hành Production

> [!IMPORTANT]
> **Quy định Cổng phát hành D08 (Release Gate):**
> 1. **Cơ sở dữ liệu Production VPS HIỆN CHƯA ÁP DỤNG V004.** Tuyệt đối không tuyên bố production đã có V004 khi chưa thực hiện thủ công.
> 2. **Rủi ro khi CD tự động kích hoạt:** Khi merge vào nhánh `dev`/`main`, quy trình CD sẽ build và deploy container backend mới. Nếu backend mới truy cập bảng `recurring_templates` trước khi migration V004 được chạy trên MySQL VPS, ứng dụng có thể gặp lỗi 500 hoặc lỗi khởi động.
> 3. **Quy trình áp dụng bắt buộc trên VPS:**
>    - **Bước 1 (Pre-check):** Kiểm tra phiên bản MySQL container trên VPS (`mysql --version`), xác nhận các bảng hiện có, thực hiện sao lưu toàn bộ database bằng mysqldump có checksum.
>    - **Bước 2 (Apply DDL):** Người vận hành được ủy quyền thực thi file `database/migrations/V004__create_recurring_templates.sql` qua lệnh `mysql -u root -p personal_finance_db < V004__create_recurring_templates.sql`.
>    - **Bước 3 (Post-check):** Chạy `SHOW CREATE TABLE recurring_templates;`, kiểm tra số lượng bản ghi các bảng D01-D07 không đổi.
>    - **Bước 4 (Deploy Backend):** Kích hoạt CD hoặc deploy image backend D08 đã được kiểm thử.
> 4. **Điều kiện Rollback:** Nếu áp dụng DDL gặp sự cố, dừng ngay lập tức; không chạy lệnh `DROP COLUMN` hoặc `DROP TABLE` khi đã có dữ liệu phát sinh; sử dụng bản snapshot backup trước release để phục hồi nếu cần thiết.

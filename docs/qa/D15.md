## 5. SQL oracle và Live HTTP

Expected result dùng Python **Decimal**, parse JSON money bằng `parse_float=Decimal`, dữ liệu SQL là DECIMAL; không tạo expected result bằng float. Số tiền trong JSON evidence được lưu dạng chuỗi để giữ độ chính xác.

Oracle tổng tháng, thay biến bằng user/kỳ fixture đã xác thực:

```sql
SELECT
  COALESCE(SUM(CASE WHEN type = 'INCOME' THEN amount ELSE 0 END), 0) AS income,
  COALESCE(SUM(CASE WHEN type = 'EXPENSE' THEN amount ELSE 0 END), 0) AS expense
FROM transactions
WHERE user_id = :jwt_owner
  AND transaction_date >= :month_start
  AND transaction_date < :next_month_start;

SELECT COALESCE(SUM(amount), 0) AS spent
FROM transactions
WHERE user_id = :jwt_owner
  AND category_id = :category_id
  AND type = 'EXPENSE'
  AND transaction_date >= :month_start
  AND transaction_date < :next_month_start;
```

- `balance = income - expense`; Dashboard summary và Reports từng tháng phải cùng bằng SQL. Expenses-by-category phải bằng cơ cấu report và tổng chi SQL.
- Report range 2026-09 → 2027-02 phải đủ sáu tháng đúng thứ tự, có tháng 02 rỗng bằng 0.
- `remainingAmount = amountLimit - spentAmount`; exceeded chỉ khi spent > limit; tiền vượt = max(0, spent − limit).
- Ngưỡng WARNING so sánh chính xác `spent * 5 >= limit * 4`, sau khi xử lý equality/over-limit. Không dùng tỷ lệ đã làm tròn để quyết định trạng thái.
- Category Budget đối chiếu SQL riêng theo owner/category/kỳ, cả usagePercentage HALF_UP 2 chữ số. Ví dụ 0.25 của category thứ hai không được cộng vào category chính.
- Delta SQL tháng 01 so với tháng 12: thu **+79.70**, chi **+0.01**, số dư **+79.69**. Ca này chứng minh oracle SQL; delta hiển thị thực tế được kiểm tra riêng trên browser (tháng 11/10 và base=0).

**Lượt cuối HTTP/SQL/DB: 46 PASS, 0 FAIL, 0 ERROR, 0 SKIPPED.** Bao gồm 43 ca HTTP đối chiếu/security, một ca delta SQL và hai ca zero mutation. Đăng ký/login/seed là setup, không cộng thành testcase PASS riêng. API thật bao phủ Dashboard summary/category, Reports, monthly/category budgets và CSV; JWT thiếu/sai/hết hạn đều 401 trên sáu endpoint. Query `userId`, GET body `userId` và body tạo fixture budget không thay JWT owner; A đọc ID category budget của B nhận 404. Đối chiếu cả hai phía A/B và CSV không có số tiền B.

**Zero mutation PASS:** trước API đọc, sau HTTP và sau Browser QA, cả tám bảng có cùng row count và SHA-256 của toàn bộ row sắp theo ID; `performance_schema.table_io_waits_summary_by_table.COUNT_WRITE` cũng giữ nguyên trên từng bảng. Không chỉ kiểm tra số row. Snapshot thực và các truy vấn SQL đã thay tham số nằm trong [live-results.json](evidence/d15-20261116-r3/live-results.json); CSV A tám dòng trong [export-A.csv.log](evidence/d15-20261116-r3/export-A.csv.log).

**Làm rõ contract:** API Category Budget cũ quy định `status=OVER_BUDGET` ngay tại đúng 100%, đồng thời `exceeded=false`. D15 UI chuyển sang `AT_LIMIT` theo yêu cầu hiện tại. Báo cáo không coi enum API đó là bug, không đổi contract. Dòng mô tả UI cũ “≥100% đỏ” trong API Contract chưa phản ánh UI D15; dùng kỳ vọng D15 của nhiệm vụ này khi kiểm tra hiển thị.
